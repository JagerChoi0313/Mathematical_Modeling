# 第三问 MATLAB 快速项目

## 运行

1. 将整个文件夹放到任意位置，不要改变 `main.m` 与 `src/` 的相对位置。
2. MATLAB 当前文件夹切换到项目根目录。
3. 运行 `main.m`。
4. `main.m` 中 `runCases = [5 6];` 表示第五、六关都运行；调试时可改成 `5` 或 `6`。

## 文件

- `main.m`：总入口。
- `src/prepare_data.m`：题目参数、天气、地图、算法配置。
- `src/best_response.m`：统一最优响应入口。
- `src/best_response_case5.m`：第五关确定天气下的完整策略最优响应。
- `src/best_response_case6_fast.m`：第六关快速场景鲁棒最优响应。
- `src/solve_game.m`：多人依次更新最优响应。
- `src/simulate_strategy.m`：正向执行最终策略。
- `src/validate_results.m`：约束复核。
- `src/plot_results.m`：输出论文图。
- `src/export_results.m`：输出 Excel。

## 第六关为何重新设计

原来的30天完整递归动态博弈状态空间过大，容易长时间停留在“生成初始可行策略”。本版保留多人最优响应和保守天气思想，但将第六关改为快速场景鲁棒近似：

- 非沙暴日按高温处理；
- “较少沙暴”仍按此前建模假设量化为最多3天；
- 用覆盖早、中、晚位置的代表性0~3天沙暴场景，而不是展开完整天气博弈树；
- 搜索若干实际有意义的最短路线模板、挖矿天数、初始资源量和村庄补给目标；
- 对每个候选方案取代表性天气场景中的最小最终资金；
- 外层仍依次计算各玩家最优响应。

因此，第六关输出是**可计算的快速稳健策略近似**。论文中不应写成“严格证明得到完整动态博弈的唯一全局纳什均衡”。
